# Персональный ассистент по обучению

Гибридная интеллектуальная система для учебного процесса: преподаватель ведёт курсы, загружает материалы и задаёт требования к лабораторным, студент сдаёт отчёты, проходит тесты и пробный экзамен, задаёт вопросы ассистенту по материалам курса.

Главная особенность — **многоагентная гибридная проверка отчётов**: символьные агенты (продукционные правила, фильтр заимствований SimHash, арбитр) работают в каскаде с нейросетевыми агентами (описание рисунков моделью зрения и три LLM-оценщика с разными позициями на моделях разных семейств). Каждое решение сопровождается протоколом, спорные случаи уходят преподавателю на ручную проверку.

```
нормализация → правила R1–R6 ─(BLOCK)→ отклонить без LLM
                              └→ SimHash ─(дубликат)→ отклонить без LLM
                                         ├→ R7: к какой лабораторной курса отчёт ближе (эмбеддинги) ─┐
                                         └→ описание рисунков (VLM, параллельно, кэш)               │
                                            → 3 оценщика параллельно ──────────────→ арбитр A1–A6
                                                                     ├→ передать преподавателю
                                                                     ├→ ручная проверка
                                                                     └→ отклонить + пояснение
```

Для студента система также строит **карту пробелов** по курсу: уровень освоения каждой темы считается символьно по результатам тестов, экзамена и отчётов (свежие весят больше, вес 0,6^k; пробел — ниже 0,7), а языковая модель по конкретным ошибкам советует, что повторить, и находит фрагменты лекций. После теста каждая ошибка разбирается со ссылкой на материал курса.

## Стек

| Слой | Технологии |
|---|---|
| Решатель задач | Python 3.11, LangGraph, LangChain (OpenAI-совместимый клиент), Natasha |
| API | FastAPI, JWT, PBKDF2 |
| База знаний | PostgreSQL 18 (курсы, лабораторные, отчёты, протоколы), Weaviate 1.29 (материалы — гибридный поиск BM25+векторы; отпечатки SimHash — метрика Хэмминга) |
| LLM и эмбеддинги | NVIDIA API Catalog по умолчанию; OpenRouter, Groq или любой OpenAI-совместимый поставщик — одной строкой в `.env` |
| Модели (NVIDIA) | ассистент, тесты, экзамен — nemotron-3-ultra-550b без рассуждения (12–30 с на ответ агента против 49–97 с у minimax-m3.1-flash, выбранной при разработке); оценщики — nemotron-3-ultra-550b (строгий и лояльный), gpt-oss-20b (объективный); модель лояльного выбрана из 8 кандидатов (`experiments/select_loyal.py`); пояснения — nemotron-3-ultra-550b; рисунки — nemotron-3.5-super-vl-120b; эмбеддинги — nemotron-3.5-embed-1b (в экспериментах — embed-8b, которая перестала отвечать; R7 на 1b даёт тот же результат) |
| Интерфейс | React 19, TypeScript, Vite, Tailwind CSS 4, shadcn/ui, TanStack Query, Recharts |
| Развёртывание | Docker Compose, nginx |

## Запуск

1. Скопируйте `.env.example` в `.env`, укажите `LLM_API_KEY` (ключ NVIDIA — build.nvidia.com → Get API Key) и случайную строку `AUTH_SECRET`.
   Другой поставщик: `LLM_PROVIDER=openrouter` или `groq`, либо `LLM_BASE_URL` + `LLM_MODEL` для любого OpenAI-совместимого API.
2. `docker compose up --build -d`
3. Откройте http://localhost:5173 (API — http://localhost:8000/api/v1, документация — http://localhost:8000/docs).

### Демонстрационные данные

При первом запуске пустая база наполняется автоматически (`SEED_DEMO=true` в `docker-compose.yml`): 2 преподавателя, 10 студентов, 10 курсов с конспектами лекций и 27 лабораторными работами, зачисления и заявки, история тестов и пробных экзаменов, 104 отчёта, оценки курсов и диалоги с ассистентом. Пароль совпадает с логином:

| Роль | Логины | Курсы |
|---|---|---|
| Преподаватель | `teacher1` (Соколов) | ООП, Базы данных, ОС, Алгоритмы, Информационная безопасность |
| Преподаватель | `teacher2` (Белова) | Веб-разработка, Компьютерные сети, Статистика, Машинное обучение, Мобильная разработка |
| Студент | `student1` … `student10` | 2–6 курсов у каждого, разная успеваемость (например, `student3` и `student7` — слабые, `student4` и `student9` — сильные) |

Конспекты лекций индексируются в Weaviate через сервис эмбеддингов (около минуты после старта); при его недоступности курсы создаются без материалов, а индексация повторяется при следующем запуске. Пересоздать данные: `docker compose exec backend python src/seed.py --reset` (данные других пользователей не затрагиваются). Запуск с пустой базой: `SEED_DEMO=false` в `.env`.

Модели оценщиков, пояснений и описания рисунков: `LLM_JUDGE_MODELS=strict=…,objective=…,loyal=…` (`same` — одна модель для всех, суффикс `@nothink` — без этапа рассуждения), `LLM_FEEDBACK_MODEL`, `VISION_MODEL`, `VISION_ENABLED`, `VISION_MAX_IMAGES` (см. `.env.example`).

Ответ ассистента передаётся потоком (`POST /api/v1/chats/{id}/messages/stream`, Server-Sent Events): интерфейс показывает шаги агента («Ищу в материалах курса…») и текст по мере генерации; если закрыть страницу, ответ всё равно допишется и сохранится в истории диалога. Обычный запрос `POST /api/v1/chats/{id}/messages` тоже работает.

Сдача отчёта асинхронная: `POST /api/v1/labs/{id}/reports` сохраняет отчёт со статусом `checking` и сразу отвечает 202, проверка идёт в фоне (не более `VERIFICATION_CONCURRENCY` одновременно), результат — в `GET /api/v1/reports/{id}`; `?wait=true` — дождаться результата в том же запросе. Прерванные перезапуском проверки возобновляются. Перед отправкой во внешние модели из отчёта удаляется титульный лист.

Если `AUTH_SECRET` не задан (или короче 32 символов), ключ подписи токенов генерируется и сохраняется в томе `uploads` — но для реального развёртывания задайте свой.

Локальная модель эмбеддингов вместо внешнего API: `EMBEDDING_PROVIDER=local` и `docker compose --profile local-embeddings up -d`.

Если Docker Hub недоступен, задайте зеркало: `IMAGE_REGISTRY=mirror.gcr.io/library`.

## Эксперимент: символьный vs нейросетевой vs гибридный

```bash
cd server
python experiments/build_dataset.py            # 45 размеченных отчётов по 3 лабораторным
python experiments/simhash_distances.py        # распределение расстояний Хэмминга
python experiments/run_experiment.py --repeats 2
```

Результаты — в `server/experiments/results/` (`summary.md`, `summary.json`, `raw.json`, `distances.json`, `e2e.xml`).

Синтетический набор, 45 отчётов (итоговая версия v4: оценщики nemotron-3-ultra-550b / gpt-oss-20b / nemotron-3-ultra-550b):

| Показатель | Символьный | Нейросетевой | Гибридный |
|---|---|---|---|
| Точность решений | 73 % | 78 % | 100 % |
| Ложные принятия | 43 % | 36 % | 0 % |
| Ложные отклонения | 0 % | 0 % | 0 % |
| Обращений к модели на отчёт | 0 | 3,0 | 2,5 |

Решения гибридного варианта совпали во всех пяти прогонах (два — `results/v1`, версия 2 — `results/v2`, промежуточная v3 + A6 + R7 с лояльным оценщиком на lightning — `results/v3a`, итоговая v4); в версии 2 у нейросетевого — 80 % и 32 %. В v3a лояльный оценщик принял 8 из 9 неполных отчётов и отчётов с внедрённой инструкцией (их отклонило правило A6), в v4 — 2 из 15 отчётов с содержательными дефектами (A6 сработало дважды, без ошибок).

Реальные отчёты, набор настройки (`python experiments/run_real.py`, версия 2): 10 обезличенных отчётов по трём дисциплинам, принятых преподавателями, + те же отчёты, приложенные к чужой лабораторной (20 проверок):

| Показатель | Символьный | Нейросетевой | Гибридный |
|---|---|---|---|
| Ложные принятия | 100 % | 0 % | 0 % |
| Ложные отклонения | 0 % | 20 % | 10 % |
| Передано на ручную проверку | 0 % | 0 % | 20 % |

Таблица синтетического набора — итоговая версия (v4); результаты версии 2 сохранены в `results/v2/`. Набор из 10 реальных отчётов проверялся версией 2 и затем использовался для выбора моделей и порогов R7.

**Отложенный набор** (`python experiments/run_heldout.py --tag v4`; версия 2 — с `LLM_JUDGE_MODELS=same LLM_JUDGE_MODEL=minimaxai/minimax-m3.1-flash VISION_ENABLED=false`): 17 реальных отчётов с 164 рисунками, не использовавшихся при настройке; каждый сдаётся по своей работе, по работе другой дисциплины и по другой работе той же дисциплины (51 проверка):

| Показатель | Символьный | Гибридный v2 | Гибридный v3 | v3 + A6 + R7 | Гибридный v4 (итоговый) |
|---|---|---|---|---|---|
| Ложные принятия | 94 % | 3 % | 0 % | 0 % | 0 % |
| Ложные отклонения | 0 % | 0 % | 0 % | 0 % | 0 % |
| Передано на ручную проверку | 0 % | 8 % | 33 % | 8 % | 4 % |
| Медианное время проверки | — | 83 с | 19 с | 23 с | 30 с |

v2 — все оценщики на одной модели, рисунки не видны; v3 — разные модели оценщиков и описание рисунков; v3 + A6 + R7 — плюс правило арбитра A6 (при 2:1 решают два уверенно согласных сильных оценщика) и правило R7 (к какой лабораторной курса отчёт ближе по эмбеддингам), лояльный оценщик ещё на nemotron-3.5-lightning-30b; v4 — лояльный оценщик заменён на nemotron-3-ultra-550b без рассуждения (выбран из 8 кандидатов на наборе настройки, `experiments/select_loyal.py`, `results/loyal_selection.json`). В v4 все три оценщика верны в 98 % проверок, A6 не понадобилось, на ручную проверку ушли 2 проверки одного отчёта (ЛР 8), который два оценщика сочли неполным. Рост времени в v4 — из-за медленной в день прогона модели зрения (медиана описания рисунков 28 с против 6–8 с ранее). A6, R7 и замена модели сделаны после просмотра результатов v3 на этом наборе, поэтому оценка v4 на нём не независима; дополнительная проверка — повторный синтетический эксперимент. R7 отметило сомнением все 34 проверки «отчёт не по своей работе» и 1 из 17 «по своей».

Синтетический набор мал и однороден: главный результат — ошибки символьного и нейросетевого вариантов относятся к разным классам отчётов, а гибридный закрывает оба; на реальных отчётах он не принимает неприемлемое, а спорное отдаёт преподавателю.

Сценарий демонстрации проверки (новый преподаватель, курсы и шесть отчётов разных категорий через API): `python scripts/demo.py http://localhost:8000` (пароль — `demo1234`).

## Структура

```
server/src/
  agents/verification/   нормализатор, правила, SimHash, описание рисунков, оценщики, арбитр, граф LangGraph
  common/                извлечение текста и рисунков (DOCX/PDF) с отметками мест рисунков
  agents/test_generator/ генерация и оценка тестов, разбор ошибок
  agents/progress/       карта пробелов (уровень освоения тем, советы)
  agents/exam/           пробный экзамен
  rag/                   RAG-агент (ReAct) и его инструменты
  recommendations/       ранжирование курсов с объяснением
  llm/                   единый клиент модели, эмбеддинги, разбор JSON, заглушка
  services/              приём и проверка отчётов
  database/              PostgreSQL и Weaviate
  auth/, api/            аутентификация и REST API
frontend/src/            страницы студента и преподавателя, протокол проверки
```
